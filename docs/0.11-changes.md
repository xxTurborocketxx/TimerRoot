# 0.11.0 changelog

## 1. Target gate: vivo/iQOO + 6.1.145

The old `ic-timer slide` only accepted `gf506252fa70d`. 0.11 splits the gate
into three layers:

| Layer | Check | Location |
|---|---|---|
| Shell preflight | `uname -r` contains `6.1.145`; `getprop`'s manufacturer/brand/model/device contain vivo/iqoo or start with V2/PD2/PD3 | `run_lpe.sh` / `device/run.sh` |
| Binary kernel gate | `osrelease` contains `6.1.145` | `ic_slide_mode` |
| Device gate | reads `ro.product.*` from `/system/build.prop` etc.; once the shell check passes it exports `IC_DEVICE_VIVO=1` to let it through | `ic_device_is_vivo` |

Test switches: `IC_ALLOW_ANY_KERNEL=1` (shell), `IC_DEVICE_ANY=1`
(binary/QEMU), `IC_SLIDE_ANY=1` (skip all checks).

## 2. Symbol tables for new builds

### Why they are needed

The slide vote is `slide = raw - (link(name) + off)`, where `link(name)` is
the **link-time** address; the mcast chain additionally needs the link-time
addresses of `__tracepoint_sys_exit`, `selinux_state`, `init_user_ns`,
`init_cred`. Builds with the same kernel minor but different link order or
config have completely different addresses (measured on two 6.1.145 builds:
`__tracepoint_sys_exit` moved from `0xffffffc00a2d1860` to
`0xffffffc00a3cb180`).

### At run time

- First the binary's built-in per-build tables are matched by `uname -r`:
  Y500/PD2506/V2506A (`gf506252fa70d` and `g3de37d73fd1d`),
  iQOO 12/PD2307/PD2329 (16.2.20.3 and 16.2.20.7, same kernel) and
  X100 Pro/X100s Pro (PD2324/V2324A/V2324HA, versions 16.2.12.0 and
  16.2.13.1) (`maybe-dirty`). Note that PD2324 and the iQOO 12 have
  exactly the same `uname -r` but all 66 addresses differ; when picking a
  known table the model is cross-checked (PD2506 / V2506 / PD2307 / PD2329 /
  V2307 / PD2324 / V2324A / V2324HA). On a match it is used directly,
  **no files needed**.
- Only unmatched builds read `IC_SYMS_FILE` (default
  `/data/local/tmp/ic-syms.txt`); the table header `build=` must equal
  `uname -r` (either side may contain the other), otherwise it is refused.
- **Specific-version detection**: the built-in tables require `uname -r` +
  model + `ro.build.display.id` to all match at once (e.g.
  `PD2307_A_16.2.20.3.W10.V000L1`). The shell exports
  `IC_DEVICE_MODEL` / `IC_BUILD_VERSION`, and the binary also reads
  build.prop. If any item mismatches, the built-in table is not used and it
  falls back to `/data/local/tmp/ic-syms.txt` / parsing; this is also the
  insurance that PD2324 and the iQOO 12, despite the same `uname`, never
  cross-select tables.
- External tables/table files are CRLF-tolerant; `ic_syms_load_file`
  strips trailing `\n` so tables generated on Windows don't fail the build
  header match.
- If the external table is also missing, only gf506252 can continue; other
  builds print: `ic-timer syms <boot.img> /data/local/tmp/ic-syms.txt` (the
  app's "parse offsets" opens the system file picker).

### The parser (`ic_syms.c`)

Inputs: Android boot v0–v4 (`ANDROID!`, kernel after the header page), raw
ARM64 Image, lz4-legacy/gzip/zlib-compressed kernels, vmlinux ELF
(.symtab), System.map/ksyms.txt text.

The ARM64 Image path is a C port of `kallsyms_py.py`:

1. Find the `0\0 1\0 … 9\0` token table header, validate 256 tokens against
   the u16 index;
2. Search the 4 MB before the token table for the marker table (first u32=0,
   subsequent deltas 0x200..0x40000);
3. From `names_offset ≈ markers_offset - last_marker` walk back at most
   0x40000 to find `num_syms` and the compressed name stream (ULEB or raw
   length);
4. Decode ~110k names, requiring `_text`/`_end`/`load_module` to exist;
5. Validate the address table with three rules — `_text`/`_end`, monotonic
   addresses, 90% inside the image (both pre-6.4 and 6.4+ layouts tried).

Outputs 66 lines of `name=0xaddr` plus the `# build=` header.

## 3. KSU handoff (`ksu_handoff.sh`)

Rewritten following the X300/t61269 flow:

1. **KMI**: with no argument, derived from `uname -r` (6.1.* →
   `android14-6.1`).
2. **Re-extract ksud every time**: no longer prefers
   `/data/adb/ksu/bin/ksud` (which may be left over from an old manager);
   instead copies every `.so` > 1 MB from the `lib/arm64/` of the APK
   directory found via `pm path`, runs `--version` and
   `late-load --help`, and prefers one that mentions
   `uapi`/`late-load`/`--kmi`; `libksud.so` is the last fallback; for
   APK-embedded (no extracted dir) builds, `unzip -p` is used.
3. **Try managers one by one**: the explicitly selected package goes first,
   then every installed manager from the KNOWN list is tried (7kimisu's
   kernel only accepts its own signature, so one wrong pick no longer
   fails outright). `me.inkdye.vivoksu`, `com.rifsxd.ksunext`,
   `me.yuki.fina` also joined the list.
4. **late-load forms**: `--allow-shell --kmi <kmi> --package-name <pkg>` →
   drop `--kmi` → drop `--package-name` → `--allow-shell` only.
5. **Success detection does not depend on `/proc/modules`**: module names
   vary and some forks hide; any one of `/sys/module/{kernelsu,ksu}`, a
   `/proc/modules` line, or `su -c id` succeeding counts as live. Polls for
   20 s after each late-load.
6. Once live, runs `ksud install` (180 s), polls su for another 30 s, then
   `am force-stop` + `monkey` to bring up the manager so its "jailbreak
   mode" page completes the userspace.
7. Only when every manager fails does it fall back to the installed
   `/data/adb/ksu/bin/ksud` (noting in the log that it is not freshly
   extracted).
8. Exit codes: 0 = module + su; 6 = live but su unavailable; 7 =
   unconfirmed.

## 4. Safe mode

- When the third argument of `ksu_handoff.sh` (or `IC_SAFE_MODE=1`) is 1,
  `disable` files are written to `/data/adb/modules/*` and
  `modules_update/*` **before** late-load. KernelSU's module loader skips
  directories containing that file (the ksud strings contain `is disabled,
  skip` / `Failed to remove disable file`).
- Already-disabled modules are not recorded twice; the paths are written to
  `/data/adb/ksu/ic-disabled-modules.txt`.
- `safemode.sh --restore` / `cleanup.sh --restore-modules` restores only
  the ones this tool recorded — it never re-enables modules the user
  disabled themselves.
- `ksud safemode`/`persist.sys.safemode` are not used: the CLI/property
  semantics differ between forks, while the `disable` file is the one
  mechanism every KernelSU/Magisk-compatible implementation honors.

## 5. Cleanup

`cleanup.sh` by default only deletes the KSU-related directories + this
tool's temp files; only `--apk` uninstalls the manager. It never touches
`/data/adb/magisk`, `post-fs-data.d`, `service.d`. Kernel modules disappear
on reboot.

## 6. Disabling USB debugging no longer reboots the phone

Symptom: after privilege escalation, disabling USB debugging rebooted the
phone. The causal chain:

1. Disabling USB debugging → adbd stops → the Shizuku service/user service
   started via ADB is killed;
2. The service's stdout/stderr pipes close;
3. A parked attempt (and the running mcast winner) get SIGPIPE on their next
   `write(2)`, whose default action kills the process;
4. The killed attempt releases the rewritten timer node →
   `posix_cpu_timers_exit → timerqueue_del/rb_next` oops →
   `panic_on_oops=1` reboot.

Fix:

- `timer_lpe.c` gained a permanent constructor `ic_ignore_sigpipe()`: the
  whole process tree (still inheriting SIG_IGN after fork/exec) ignores
  SIGPIPE; a broken log pipe only yields EPIPE.
- `run_lpe.sh` / `run.sh` both `trap '' PIPE HUP INT TERM`.
- `IcService.start` launches the whole chain with
  `/system/bin/setsid sh <script>`, putting the plan into its own session;
  when USB debugging is disabled, adbd's process-group kill cannot reach
  the parked attempts. The device-side `run.sh` also `setsid`s before exec.
- None of these changes touch the exploit's address/attempt logic — only
  how it stays alive.
